# Doctor Plus

واجهة تجريبية عربية وإنجليزية لمنصة رعاية صحية، مستوحاة من لوحات تطبيقات الحجز الطبي. صُممت لتعمل كتجربة جوّال على iPhone وAndroid، وتتضمن ثلاث مساحات: المريض والطبيب والإدارة.

## التشغيل

المتطلبات: Node.js 20 أو أحدث وnpm.

```bash
npm ci
npm run dev -- --host 0.0.0.0 --port 4174 --strictPort
```

افتح الرابط المحلي الذي يعرضه Vite. استخدم قائمة الجهاز أعلى المعاينة للتبديل بين iPhone وPixel 10. من زر الدور بجانب اللغة، بدّل بين المريض والطبيب والإدارة.

## ما يتضمنه النموذج

- **المريض:** البحث عن الأطباء، التخصصات والخدمات، اختيار الطبيب والموعد، تأكيد الحجز، المواعيد والملف الصحي.
- اختصارا الصيدلية والتحاليل يعرضان خيارات منفصلة: البحث عن دواء أو رفع وصفة أو طلب توصيل، وحجز تحليل أو استعراض التحاليل أو رفع طلب طبي.
- كتالوج صحي موسّع مستوحى من الخدمات العامة في e‑Nabız: الزيارات، التشخيصات، التصوير، التقارير، الوصفات البصرية والدوائية، اللقاحات، الحساسية، ملاحظات الطوارئ، مؤشرات الصحة، مشاركة السجل، سجل الوصول، التبرع، والأجهزة المرتبطة.
- صفحة صحتي بخلفية رسم طبي صحي، وصفحات مستقلة للوصفات والتحاليل والسجلات والحساسية، مع إضافة وتعديل وحذف وحفظ محلي للبيانات.
- صفحة نصائح صحية بقائمة متابعة يومية محفوظة محلياً، وروابط سريعة لتحديث مؤشرات الصحة.
- حفظ الأطباء في المفضلة، وتعديل بيانات الحساب وملخص المعلومات الصحية محلياً.
- صفحة الحساب تشمل إدارة أفراد العائلة، تعديل معلومات التأمين، لغة الحساب وتفضيلاته، إعدادات الإشعارات، ومركز دعم يحفظ الطلبات التجريبية محلياً.
- يمكن للمريض والطبيب اختيار صورة شخصية؛ تُضغط الصورة وتُحفظ محلياً في النموذج.
- مراسلة الطبيب من بطاقة الطبيب أو الموعد، مع محادثة تجريبية بالعربية والإنجليزية.
- حجز موعد في العيادة أو مكالمة صوتية أو فيديو؛ يظهر نوع الموعد في التأكيد والتفاصيل.
- **الطبيب:** لوحة اليوم، جدول المواعيد، قائمة المرضى، الشهادات، إعدادات ملف الطبيب، والمساعدة.
- **الإدارة:** مؤشرات المنصة، إدارة الأطباء والمرضى والحجوزات والخدمات، نشاط المنصة، وتقارير تجريبية.
- يبدأ التطبيق بشاشة دخول تحمل شعار Doctor Plus، وبطاقة ترحيب مصورة بطبيبة وخيارات مرئية للمريض والطبيب والإدارة. التسجيل والدخول تجريبيان فقط، ويمكن الوصول إلى الشاشات التعريفية من زر الرجوع.
- العربية RTL والإنجليزية LTR، مع تبديل فوري من الواجهة.
- علامة Doctor Plus برسمة السماعة الطبية والعلامة المائية الخفيفة نفسها.
- بيانات تجريبية وتفاعلات محلية لعرض تدفقات المنتج.

## الفحص البصري

ابدأ التطبيق على المنفذ `4174` ثم شغّل:

```bash
npm run qa:visual
```

يحفظ الفحص لقطات في `qa/screenshots/` ويتحقق من شاشة الدخول الأولى وخلفيتها الطبية وبطاقة الطبيب وخيارات أدوار الحساب بالعربية والإنجليزية، وألواح الصيدلية والتحاليل باللغتين؛ إضافة إلى أحجام الهاتف واللوحي وسطح المكتب، نافذة سطح مكتب قصيرة، مساحتي عرض تمثلان تكبير 125% و150%، اتجاهي RTL/LTR، أدوار المستخدمين، انتقال دائرة البار إلى القسم المختار، ملف الحساب وصور المريض والطبيب، إضافة وتعديل وحذف أفراد العائلة، تعديل التأمين، إعدادات الحساب والإشعارات والدعم، صفحات السجل الصحي والنصائح بالعربية والإنجليزية، إضافة وتعديل وحذف بيانات طبية تجريبية، الخدمات، المفضلة وتعديل الملف الصحي والشخصي، مراسلة الطبيب واتجاه سهم الرجوع، خيارات موعد العيادة والصوت والفيديو وتأكيد الحجز، واختيار Pixel 10. يتطلب الفحص تثبيت Chromium لـ Playwright (`npx playwright install chromium`) عند عدم وجوده محلياً.

فحوصات إضافية:

```bash
npm run check:runtime
npm run build
```

## النشر من GitHub Pages

يوجد سير عمل GitHub Actions في `.github/workflows/deploy-pages.yml` يبني التطبيق وينشره تلقائياً عند كل push إلى `main`. بعد رفع التغييرات، افتح المستودع في GitHub ثم:

1. ادخل إلى **Settings → Pages**.
2. في **Build and deployment → Source** اختر **GitHub Actions**.
3. افتح تبويب **Actions** وانتظر نجاح **Deploy GitHub Pages**.
4. سيظهر رابط الموقع في **Settings → Pages**، ويكون عادةً `https://ainova360.github.io/Doctor-plus-app/`.

يُبنى الموقع لمسار المشروع `/Doctor-plus-app/` وتُعاد كتابة مسارات الصور والأيقونات تلقائياً. للتحقق من حزمة Pages محلياً (بما يشمل مسار المشروع واللغتين):

```bash
npm run qa:pages
```

أما إعدادات GitHub Pages الخاصة برابط المستودع فتُطبقها عملية GitHub Actions عند النشر. أعد كذلك `npm run qa:visual` عند تعديل واجهات التطبيق.

**مهم للخصوصية:** رابط GitHub Pages يكون متاحاً للعامة. المستودع الحالي خاص؛ GitHub يسمح بنشر Pages من مستودع خاص على الخطط المدفوعة المؤهلة. إذا كان حسابك على الخطة المجانية، ستحتاج إما إبقاء المستودع خاصاً واستخدام استضافة أخرى، أو جعل المستودع عاماً بعد الموافقة لأن ذلك يكشف ملفات المصدر أيضاً. لا تغيّر خصوصية المستودع قبل اتخاذ هذا القرار. راجع [حدود GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

لا توجد مفاتيح تشغيل مطلوبة لهذا النموذج؛ لا ترفع بيانات صحية حقيقية أو ملفات سرية.

هذا نموذج واجهات فقط: المحادثات والحجوزات والمرضى والمؤشرات وبيانات الدخول تجريبية ومحلية، والرسائل والمكالمات لا تتصل بطبيب حقيقي. صور الأطباء صور تجريبية من Unsplash والأسماء غير مرتبطة بأصحاب الصور. لا توجد قاعدة بيانات أو تسجيل دخول حقيقي أو اتصال صوت/فيديو أو تكامل دفع أو اتصال بمستشفى أو وصفات طبية فعلية. ولتحويله إلى تطبيق إنتاجي أو نشره كتطبيق أصلي عبر المتاجر، يلزم بناء API وتسجيل موثوق وتدقيق للخصوصية وسلامة البيانات ثم تغليف/تنفيذ الهاتف بشكل أصلي أو PWA بحسب قرار المنتج.

قائمة الخدمات مستوحاة من [دليل e‑Nabız الرسمي](https://enabiz.gov.tr/Yardim/Index/) ومن [دليل الاستخدام المنشور من وزارة الصحة التركية](https://www.enabiz.gov.tr/document/WebKILAVUZ.pdf). Doctor Plus نموذج مستقل؛ لا يوجد اتصال بحساب e‑Nabız أو سجلات وزارة الصحة، ولا ينبغي إدخال بيانات صحية حقيقية في هذه النسخة التجريبية.
